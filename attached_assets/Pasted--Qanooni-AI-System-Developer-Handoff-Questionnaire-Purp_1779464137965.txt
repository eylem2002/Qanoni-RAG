# Qanooni AI System — Developer Handoff Questionnaire

> **Purpose:** Critical questions to ask the original developer before they hand off the system. Covers design decisions, known issues, testing, deployment, and future constraints.

---

## 1. THE FALSE POSITIVE CHANGES MYSTERY 🔴

### 1.1 Civil Law Rendering Noise
- **The symptom:** Between two scrapes, 17 articles in قانون المدني showed as "modified" (articles 5, 50, 53, 60, 449, etc.) but the legal team likely didn't see any actual law changes on lob.gov.jo.
- **Q1.1.1:** Did you manually verify these 17 "changes" on lob.gov.jo's website? Are they real legal amendments, or rendering/whitespace noise?
- **Q1.1.2:** Have you ever run the scraper twice in succession (same day, no time between runs) and checked if the same articles show as "changed" again?
- **Q1.1.3:** The `normalize()` function in `extractArticles()` collapses whitespace with `/[ \t]+/g` and blank lines with `/\n{3,}/g`. Are there other sources of variation you discovered?
  - Inconsistent punctuation?
  - Trailing spaces in article text?
  - The "ارتباطات المادة" links rendering differently?
- **Q1.1.4:** If these are false positives, what's the best way to fix it without accidentally missing real changes?

### 1.2 Change Detection Confidence
- **Q1.2.1:** How confident are you that the current regex for parsing article boundaries is 100% correct? Have you tested it against all 2,295 articles manually?
- **Q1.2.2:** Are there any articles in the 4 laws that have:
  - No article heading (missing "المادة X")?
  - Malformed headings?
  - Nested or conditional article structures?
- **Q1.2.3:** The regex assumes "المادة X" format. What if lob.gov.jo changes the heading format in the future?

## 2. PUPPETEER & CHROMIUM 🔧

### 2.1 The Critical Homepage Warmup
- **Q2.1.1:** You discovered that skipping the homepage warmup causes wrong content to load. Was this a one-off bug on a specific day, or does it happen *every time* without the warmup?
- **Q2.1.2:** Have you tested navigating directly to a law URL (without homepage warmup) in a fresh browser session? Did you see the same wrong-content issue?
- **Q2.1.3:** The 3-second pause after `networkidle0` — is 3 seconds the minimum, or is there headroom? What happens if you use 1 second? 2 seconds?
- **Q2.1.4:** Why does Angular's RSA session initialization require hitting the homepage? Is there a way to initialize the session programmatically via JavaScript without navigating?

### 2.2 Chromium Process Management
- **Q2.2.1:** Have you run `ps aux | grep chromium` during a scrape to see how many processes spawn? Is it 1, 5, 10?
- **Q2.2.2:** If a law fails mid-scrape (e.g., timeout), does the `finally` block always execute, or are there edge cases where the browser leaks?
- **Q2.2.3:** The `--single-process` flag reduces memory. Have you measured memory usage with/without it? What's the peak RAM during a full scrape?
- **Q2.2.4:** Replit sometimes restarts the Nix environment. When that happens, does the Chromium path discovery gracefully fall through to the next option, or does the scraper crash?

### 2.3 Content Verification Thresholds
- **Q2.3.1:** The 8,000-character threshold for `body.innerText` — how was this number chosen? Did you test it against all 4 laws to find the minimum real law size?
- **Q2.3.2:** What if lob.gov.jo loads the page shell (with "رقم التشريع") but the actual article text is still loading? Could the 8,000 check pass prematurely?
- **Q2.3.3:** The 45-second timeout on `waitForFunction` — have you ever hit this timeout? What does the error handling do if it times out?

## 4. DATABASE DESIGN 🗄️

### 4.1 Schema & Normalization
- **Q4.1.1:** Why store `full_text` in the same `laws` table instead of a separate `law_texts` table? Is it a query performance choice?
- **Q4.1.2:** The `law_versions` table stores snapshots. Do you ever query the history to calculate diffs between non-consecutive versions (e.g., version 3 vs. version 5)?
- **Q4.1.3:** The `law_changelog.affected_contract_types` is a JSONB array. Have you considered a separate `changeset_contract_types` junction table for easier querying?
- **Q4.1.4:** Is there ever a need to know *why* a change was made (amendment reason, legislative intent)? Should there be a `change_reason` or `legislative_reference` field?

### 4.2 Indexing & Performance
- **Q4.2.1:** What indexes exist on the database? (law_id, article_number, change_type, acknowledged_at, etc.)
- **Q4.2.2:** The `full_text` column can be 277 KB. Do you have a query performance issue if a user tries to fetch all laws at once?
- **Q4.2.3:** As the changelog grows (after 1 year = ~52 scrapes), will the `law_changelog` table become slow to query?

### 4.3 Data Integrity
- **Q4.3.1:** What happens if a scrape partially completes? (e.g., 3 of 4 laws succeed, 1 fails) Does the database get into an inconsistent state?
- **Q4.3.2:** Is there a backup/restore procedure? If the database gets corrupted, how do you recover?
- **Q4.3.3:** The `law_versions` table preserves history. How long do you keep versions? (Forever? 1 year? 2 years?)
